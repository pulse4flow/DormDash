# DormDash: แผนเวอร์ชันแรก (ร่าง)

สถานะ: แผนสำหรับหารือ ยังไม่เริ่มพัฒนาฟังก์ชัน  
กลุ่มทดลอง: ผู้ประกอบการที่พักขนาดเล็ก 1 แห่ง เช่น รีสอร์ทหรือเซอร์วิสอพาร์ตเมนต์

## เป้าหมาย

ให้เจ้าของและพนักงานเห็นว่า **วันนี้มีใครเข้า–ออก ห้องไหนพร้อมใช้งาน และงานใดต้องทำ** ในหน้าเดียว โดยเริ่มจากการบันทึกข้อมูลด้วยตนเอง ไม่ต้องเชื่อมระบบจองภายนอก

## ขั้นตอนทำงานหลัก

1. เจ้าของตั้งค่าที่พัก ห้อง และบัญชีพนักงาน
2. พนักงานบันทึกการจอง พร้อมวันเข้าพัก วันออกพัก จำนวนผู้เข้าพัก และห้อง
3. หน้า “วันนี้” แสดงรายการเข้า–ออก ห้องที่พร้อม/ไม่พร้อม และงานที่ค้าง
4. พนักงานเช็กอินและเช็กเอาต์; สถานะห้องเปลี่ยนตามขั้นตอนงาน
5. แม่บ้านรับงานเตรียมห้องและยืนยันเมื่อห้องพร้อม
6. พนักงานเปิดงานซ่อม ติดตามสถานะ และปิดงานเมื่อเสร็จ

## ฟังก์ชันที่วางไว้สำหรับเวอร์ชันแรก

| ส่วน | ขอบเขตขั้นต่ำ |
| --- | --- |
| ที่พักและห้อง | ตั้งค่าที่พักหนึ่งแห่ง เพิ่ม/แก้ไขห้อง และดูสถานะห้อง |
| การจอง | เพิ่ม/แก้ไข/ยกเลิกการจองแบบบันทึกเอง; ป้องกันการจองห้องทับช่วงเวลา |
| ผู้เข้าพัก | เก็บข้อมูลติดต่อเท่าที่จำเป็นและผูกกับการจอง |
| การเข้าพัก | เช็กอิน เช็กเอาต์ และดูผู้ที่กำลังเข้าพัก |
| งานทีม | งานเตรียมห้องและงานซ่อม พร้อมผู้รับผิดชอบและสถานะ |
| ภาพรวมรายวัน | รายการเข้า–ออกวันนี้ ห้องพร้อมใช้งาน และงานค้าง |
| สิทธิ์ | เจ้าของ/ผู้จัดการ และพนักงาน; จำกัดข้อมูลตามหน้าที่ |

## โครงสร้างระบบที่เสนอ

- ใช้ Next.js, TypeScript, Prisma และ PostgreSQL ที่โปรเจกต์มีอยู่ต่อ
- เพิ่มข้อมูลหลักเป็น `Property`, `Room`, `Guest`, `Reservation`, `Stay` และ `WorkOrder` โดยออกแบบให้ทุกข้อมูลผูกกับที่พัก
- ใช้ `WorkOrder` เป็นแกนงานแม่บ้านและงานซ่อม แต่แยกประเภทและขั้นตอนงานให้ชัด
- เริ่มจากเว็บที่ใช้บนมือถือได้; ยังไม่จำเป็นต้องสร้างแอปมือถือแยก
- ให้ข้อมูลการจองและผู้เข้าพักอยู่ในฐานข้อมูลกลาง ไม่เก็บเฉพาะเบราว์เซอร์

## สิ่งที่ยังไม่รวมในเวอร์ชันแรก

รับจองออนไลน์, เชื่อม OTA/channel manager, ชำระเงิน, ออกใบกำกับภาษี, ตั้งราคาห้องอัตโนมัติ, หลายสาขา, สัญญาเช่า/ค่าเช่ารายเดือน และระบบบัญชี

## ก่อนเริ่มพัฒนา

สัมภาษณ์ผู้ประกอบการ 3–5 รายเพื่อยืนยันขั้นตอนรับจอง การส่งต่องานแม่บ้าน ปัญหาห้องทับ และข้อมูลที่ต้องเห็นในแต่ละวัน จากนั้นสรุปหน้าจอและเกณฑ์ยอมรับของเวอร์ชันแรกอีกครั้ง

## เกณฑ์ว่าเวอร์ชันแรกสำเร็จ

ผู้ประกอบการทดลองใช้กับงานจริงหนึ่งแห่งได้ครบหนึ่งรอบ ตั้งแต่บันทึกการจองจนเช็กเอาต์ โดยรู้สถานะห้องและงานค้างโดยไม่ต้องถามกันผ่านช่องทางอื่น
